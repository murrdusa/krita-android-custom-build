## P0 — crashes, document safety, navigation blockers

- **1.6 Home/save behavior:** Currently tapping Home on a dirty named canvas **forces a Save prompt**. User requests: **Home should automatically save a named project** and return to Home without the confirmation prompt. **Exception: unnamed/untitled documents** should not silently save under a guessed path; decide safe unsaved-draft/Save As flow. Respect explicit **Close → Don't Save** semantics; never silently preserve intentionally discarded edits. Distinguish Home navigation from Close.
- **1.7 Multiple canvases:** User asks whether **two canvases can be open at once**; existing native view stack supports multiple open documents, but clarify distinction between multiple open drawings switched in app and true simultaneous *side-by-side* display. Do not assume user specifically requested split-screen yet.
- **1.7 Open from canvas Documents menu:** Opening a document from the **in-canvas Documents** menu makes the **top toolbar disappear**. Four-finger hide-UI gesture OFF then ON restores the toolbar. Fix activation/layout/state synchronization, not a workaround requiring the gesture. **Brush name label becomes unreadable** after this path; ensure sufficient contrast, truncation, repaint on canvas switch.
- **Tools chooser touch scrolling regressed:** Scrolling Tools grid by finger no longer works well; distinguish swipe scrolling from tapping a tool. This was previously fixed and regressed. Address touch event filters/popup modality in actual current tool chooser.
- **Deleting groups can crash the app**, intermittently. Reproduction likely includes deleting a group with content or nested groups; test with throwaway drawings and native undo transactions. **Group display also becomes inconsistent** after group deletion (single stray layer, nothing selected, stale hierarchy) until another UI operation refreshes the rail. Fix both crash/root cause and asynchronous selection/tree refresh rather than only cosmetically hiding it. Highest-priority layer correctness issue.

## P1 — active drawing interactions, touch ergonomics, functionality

- **2.7 Preset browser:** Brush names are often **unreadable**; fix foreground/background contrast and clipping. The brush thumbnail grid **wastes large inter-item space**. User wants closely packed thumbnails, with only a **small caption area per brush**, concise/truncated text when long (or sensible text-size adaptation). No stretched/distorted thumbnails; keep comfortable touch targets.
- **2.8 Brush controls:** Brush size and opacity currently work. **Add Size and Opacity sliders to the actual Brushes menu/preset UI**, with **Flow only where applicable**, in addition to existing floating sliders. Controls must be clearly reachable and touch-friendly.
- **2.16 Mirror painting unexpected background echo:** With symmetry/mirror active, certain soft/feathered pencil-type brushes painting onto an existing colored layer (example: a gray pencil stroke on green) produce expected mirrored pencil strokes **plus a large unexpected mirrored halo/chunk of the underlying green color on the other side**. Compare native Krita symmetry to distinguish engine blending/compositing issue, brush preset behavior, or our UI toggling different mirror mode. Must reproduce on separate same-layer vs separate-layer tests before changing engine. User doubts this is intentional.
- **2.19 Gesture configuration:** Scrolling a gesture-settings page **from a dropdown** opens the dropdown instead of scrolling. Need gesture disambiguation between tap (open selector) and vertical swipe (scroll parent), preserving finger and stylus. Generic scrolling elsewhere works. Report says gesture settings otherwise working.
- **Missing-feature check:** User asks **whether one-finger tap color palette** is present. Inspect current gesture/action bindings; report what exists vs planned, and implement only if intended behavior/trigger is clear.
- **Numeric values with suffixes:** Input fields showing values like `123 px` place cursor **after non-removable `px` suffix** on initial tap, forcing precise manual cursor placement to edit numbers. On focus/tap select the numeric portion (or whole editable value), ensure suffix is a separate label / spinbox suffix, never block deleting/replacing the number. Apply consistently to pixel width, height, and other numeric fields in mobile settings and tool dialogs.
- **3.15 Opacity:** Slider works, but should be **more touch-friendly** (track/handle or larger hit area) and respond predictably to finger dragging.
- **3.14 Alpha Lock:** Functional and frequently used. **Promote Alpha Lock to the first/main layer-options action grid**, rather than burying it in extended menu. Ensure state displayed and checked correctly for selected paint layer.

## P1/P2 — layer rail hierarchy and action design

- **Group/folder indicator:** Current group is rendered almost like another full paint layer. User wants a **shorter, visually obvious folder/group header**, closer to Krita's folder metaphor rather than a layer tile; **do not show Lock/Unlock on the group header**, only visibility in this compact UI. Group marker should not be confused with a regular paint layer. The underlying `KisGroupLayer` remains a genuine Krita compositing group; do not invent a separate file object.
- **Group boundaries:** All children of a group should be enclosed within a **clear high-contrast border**. Multiple nested group boundaries must be distinct and non-overlapping; collapsing/expanding should be obvious. User says grouping, nested groups, pinch grouping, and dragging in/out generally work.
- **Clipping UI:** Current functionality apparently works but **clip affordances/visual grouping are not obvious or clean enough**. Make it look/behave intuitively like mainstream drawing apps: show clip state and target (first unclipped eligible layer below), visually distinguish clip run from group hierarchy; avoid clutter and unnecessary surrounding area. User has not yet tested latest clipping checklist cases deeply.
- **Rename by direct name tap:** The existing Rename action works, but **tapping a layer name wherever displayed** should open a quick, touch-friendly rename dialog; direct text tap should not conflict with selection/drag on the thumbnail.
- **3.16 Blend-mode menu:** Current custom menu appears to flatten **every native blending mode into one overwhelming list**. Redesign using a short **Favorites/common** group at top (Normal, Multiply, Overlay, Screen, Erase, Darken, Lighten, Color Dodge, Burn, etc. supported by selected color space) followed by **expandable categories** such as Arithmetic, Binary, Darken, HSI, HSL, HSV, HSY, Lighten, Misc, Mix, Modulo, Negative, Quadratic. **Must dynamically use Krita's real composite-op registry**, preserve color-space availability, indicate current mode, provide simple finger scrolling; stock Krita screenshot is the reference. Do not hardcode unsupported modes or change actual compositing behavior.
- **3.8/3.9 creation confusion:** Group commands are inconsistent: some offer **select layers to put in group**, but `+ Group` merely creates an **empty group**. Explain difference; consider explicitly labeling **New empty group** vs **Group selected layers**. User rarely uses unusual layer types and needs practical test instructions.
- **Dragging into empty group:** User reports **difficulty, intermittently apparently impossible**, moving a layer into an *empty* group; nesting into existing nonempty groups works. Ensure intentional drop zone for empty group, clear feedback and correct native parent move, without accidentally reordering.
- **3.9 unfamiliar native types:** Explain effects and usable checks for Krita's **Paint Layer, Group Layer, Vector Layer, Fill Layer, Filter Layer, File Layer, Clone Layer; Transparency Mask, Filter Mask, Transform Mask, Selection Mask, Colorize Mask** (and optional Fast Color Overlay). Do not assume user tested these types. Keep all accessible even if user doesn't regularly use them.
