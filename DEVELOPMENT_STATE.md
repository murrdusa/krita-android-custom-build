# Current development handoff — 2026-11-09

Read [AGENTS.md](AGENTS.md) first. This file is updated as implementation progresses; it is **not** an instruction to repeat old work. Read GitHub `main` and the local build status for live state.

## Current implementation

- **Native drawing host:** `MobileLightweightCanvasHost` now launches directly as the Android top-level. Normal startup no longer creates Krita's desktop `KisMainWindow` or a second V2 wrapper window; diagnostic-only failure handling replaces the V2/V3 recovery-mode sequence. Code: `mobile_core/engine_only_bootstrap.cpp`, `engine_only_startup_policy.h`.
- **Krita engine session:** `mobile_core/krita_engine_session.h` creates the native view manager and document/view/command ports. It uses Krita's actual brush, canvas, layers, undo, and KRA file engine; it does not recreate those engines.
- **Android process-level startup:** the patched `krita/main.cc` now dispatches ordinary Android launches directly to `MobileKritaAndroidRuntime::launch`, **without calling `KisApplication::start`**. The new module initializes native resources/plugins, Krita's native document factory, long-press and stylus settings, display scaling, and opens the independent drawing host. Explicit file/session/batch invocations temporarily retain original Krita startup. This has passed a full PC Android compile, but not on-device startup verification. It still uses Krita's Qt application object and native executable library; it is not yet a fully separate CMake binary.
- **Native application entry module:** `mobile_core/krita_application_entry.cpp` now owns startup eligibility and the single-window launch decision. Krita's application class delegates to it instead of constructing the Android host directly. Still not a new process `main()`.
- **Independent Android install identity:** debug APK package is `org.krita.mobilestudio.debug`, launcher label **Krita Mobile Studio**. Configured by `apply_mobile_shell.py`, packaged by `build-in-krita-container.sh`. It is separate from the original Krita installation.
- **Engine initialization separated:** resource type, resource loader/cache, paint-op/tool/plugin registry setup lives in `mobile_core/krita_engine_initialization.cpp`, compiled separately in Android `kritaui`. Normal launches bypass `KisApplication::start` but retain the `KisApplication` Qt object for event handling; documents still use the real Krita `KisPart` service. Explicit sessions/batch operations retain legacy startup for now.
- **Latest verified full PC Android build at time of note:** revision `643d461ad05f4f834762a3b463b8d25975b25a51`, **SUCCESS**, recorded on [Issue #1](https://github.com/murrdusa/krita-android-custom-build/issues/1). Includes independent startup and the Android native file-intent queue. Android Share (ACTION_SEND) additions after this SHA are still awaiting PC compilation. Build success alone is not a device test; compare exact SHAs.
- **Latest device-confirmed baseline (2026-11-09):** on Galaxy Z Fold 6, user marked PASS for direct startup, stylus painting and pressure, touch-operated Brushes/Layers/Color, Undo/Redo and KRA save/close/reopen; no issues reported. This baseline predates the Android file-intent routing changes below. No APK was automatically uploaded.

- **Android external document intents:** PC-compiled `mobile_core/android_document_intents.{h,cpp}` queues cold-start files and forwards Java/Qt/remote Open requests to the existing native Krita document importer. Opens queued files before creating a blank canvas. Supports content-provider URIs and normalizes file:// URLs. The additional Android single-file Share intent filter and EXTRA_STREAM parser are now source-implemented, awaiting local PC APK compile and device test.
